# Keitaro Flow

Keitaro Flow — веб-приложение для создания кампаний Keitaro и управления потоками офферов. Приложение работает с Keitaro через Admin API, а локальные настройки офферов и журнал изменений хранит в MongoDB.

**Стек:** React, Vite, Node.js, Express, MongoDB.

## Реализованный функционал

- Создание кампании с гео-потоком на заданный URL и потоком выбранного стартового оффера.
- Название кампании автоматически формируется по схеме `test_<введённое значение>_campaign`. URL-alias создаётся автоматически.
- Включение и деактивация офферов без удаления локальной записи. Неактивные офферы отображаются с долей `0%` и не отправляются в Keitaro.
- Закрепление процентной доли оффера. При изменении состава потока закреплённые доли сохраняются, а оставшаяся часть распределяется между активными незакреплёнными офферами.
- Подготовка изменений в черновике: изменённые поля подсвечиваются, «Применить изменения» отправляет их, «Сбросить» возвращает последнее загруженное состояние.
- Синхронизация с Keitaro: добавленный там в поток оффер появляется активным; удалённый из потока сохраняется в приложении и становится неактивным. Восстановить оффер можно, если он снова доступен в каталоге Keitaro.
- Запоминание выбранной кампании между перезагрузками страницы.
- Просмотр статистики кампании за текущий день.

## Требования

- Node.js версии `22.12` или новее.
- Доступная MongoDB и строка подключения к ней.
- Доступ к Keitaro Admin API с разрешениями на чтение и изменение кампаний, потоков и офферов.
- API-ключ Keitaro.

## Установка и запуск

Все команды выполняйте из корневой папки проекта.

### 1. Подготовьте `.env`

Скопируйте шаблон при первой настройке:

```bash
cp .env.example .env
```

Если `.env` уже существует, не перезаписывайте его: проверьте и измените нужные значения в существующем файле.

Откройте `.env` и укажите параметры своего окружения:

| Переменная | Что указать | Пример |
|---|---|---|
| `MONGODB_URI` | Адрес MongoDB | `mongodb://127.0.0.1:27017/keitaro_wrapper` |
| `KEITARO_BASE_URL` | Адрес панели Keitaro без `/admin_api/v1` | `https://your-tracker.example` |
| `KEITARO_API_KEY` | Ключ Admin API | Получите в **Профиль → API-ключи** в Keitaro |
| `DEFAULT_DOMAIN` | Домен, точно совпадающий с доменом в Keitaro; можно оставить пустым, если домен один | `track.example.com` |
| `DEFAULT_GROUP_NAME` | Название группы кампаний в Keitaro | `FORTESTS` |
| `DEFAULT_SOURCE_NAME` | Название источника трафика в Keitaro | `FORTESTS` |
| `GOOGLE_URL` | URL назначения для гео-потока | `https://www.google.com` |
| `PORT` | Порт API приложения | `3000` |
| `KEITARO_TIMEOUT` | Таймаут запросов к Keitaro в миллисекундах | `20000` |

Приложение автоматически добавляет к адресу Keitaro путь `/admin_api/v1`. Если адрес панели заканчивается на `/admin`, этот суффикс можно указать или опустить.

Адрес панели не является секретом уровня API-ключа, но раскрывает адрес вашего трекера. Поэтому в `.env.example` и документации используется нейтральный пример. Укажите реальный адрес только в локальном `.env`; не публикуйте API-ключ и не добавляйте `.env` в Git.

### 2. Убедитесь, что MongoDB запущена

Для локальной MongoDB оставьте значение `MONGODB_URI` из примера. Если MongoDB размещена на другом сервере, укажите её URI в `.env`. До запуска приложения сервер MongoDB должен быть доступен.

### 3. Установите зависимости последовательно

```bash
npm ci
npm --prefix server ci
npm --prefix client ci
```

Запускайте команды по очереди из корневой папки проекта.

### 4. Запустите приложение

```bash
npm run dev
```

Откройте адрес Vite из вывода терминала — обычно это [http://localhost:5173](http://localhost:5173). API работает на [http://localhost:3000](http://localhost:3000).

### Production-сборка

```bash
npm run build
npm start
```

Express обслуживает production-клиент из `client/dist`.

## Создание кампании

| Поле | Что вводить | Пример |
|---|---|---|
| **Название кампании** | Короткое понятное название. `test_` и `_campaign` добавятся автоматически. | `bakyt` → `test_bakyt_campaign` |
| **Гео** | Двухбуквенные коды стран, разделённые запятыми. Используйте коды, поддерживаемые Keitaro. | `AU, MX, RO` |
| **Стартовый оффер** | Найдите и выберите существующий оффер Keitaro по названию или ID. | `#123 · Example offer` |
| **Домен, группа, источник** | Эти значения отображаются в «Дополнительных настройках», но изменить их в форме нельзя. Они заполняются из настроек `.env` и доступных значений Keitaro. | Домен `track.example.com`; группа и источник `FORTESTS` |

Домен, группа и источник заблокированы намеренно: эти параметры связаны с настройками проекта и требованиями к созданию кампании. Случайное изменение может привести к некорректной конфигурации. Если значение пустое или неверное, измените `DEFAULT_DOMAIN`, `DEFAULT_GROUP_NAME` или `DEFAULT_SOURCE_NAME` в `.env` и перезапустите сервер. Если в Keitaro только один домен, приложение может выбрать его автоматически.

Например, для кампании с названием `bakyt`, гео `AU, MX` и выбранным оффером приложение создаст кампанию `test_bakyt_campaign`, гео-поток на `GOOGLE_URL` и поток выбранного оффера.

## Работа с долями офферов

1. Измените активность, закрепление или долю оффера либо добавьте оффер в поток.
2. Проверьте черновые значения: изменённые поля подсвечиваются жёлтым.
3. Нажмите **«Применить изменения»**, чтобы сохранить корректировки, или **«Сбросить»**, чтобы отменить их.

Перед применением сумма долей активных офферов должна составлять `100%`. Доля неактивного оффера равна `0%`. Закреплённые доли не меняются при перераспределении; свободный остаток распределяется между активными незакреплёнными офферами. Оффер, удалённый из общего каталога Keitaro, нельзя восстановить до его возвращения в каталог.

## Где получить API-ключ Keitaro

Войдите в административную панель Keitaro, откройте **Профиль → API-ключи**, создайте ключ для приложения и сохраните его в `KEITARO_API_KEY` в `.env`. Не передавайте ключ в клиентский код и не публикуйте его.

## API приложения

| Метод | URL | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка состояния |
| `GET` | `/api/meta` | Домены, группы, источники и значения по умолчанию |
| `GET` | `/api/offers?q=` | Поиск офферов |
| `POST` | `/api/campaigns` | Создание кампании |
| `GET` | `/api/campaigns?q=` | Список кампаний |
| `GET` | `/api/campaigns/:id` | Кампания, потоки и статистика за сегодня |
| `POST` | `/api/campaigns/:id/streams/:sid/offers` | Добавление или восстановление оффера |
| `PATCH` | `/api/campaigns/:id/streams/:sid/offers/:oid` | Изменение активности, закрепления или доли |
| `PUT` | `/api/campaigns/:id/streams/:sid/offers` | Применение изменений офферов |
