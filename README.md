# Keitaro Flow

Веб-приложение для создания и редактирования кампаний Keitaro. Стек: **MongoDB, Express, React, Node.js**.

## Возможности

- Создание кампании с гео-потоком на Google и оффер-потоком.
- Управление потоками и статистикой офферов.
- Деактивация оффера без потери локальной записи; при повторной активации проценты всех активных незакреплённых офферов пересчитываются поровну.
- Закреплённые проценты сохраняются; оставшаяся доля равномерно распределяется между активными незакреплёнными офферами.
- Если оффер удалён из потока кампании, он остаётся в приложении с долей 0%. Если он всё ещё есть в общем каталоге Keitaro, его можно включить в приложении: он снова попадёт в поток, а доли незакреплённых офферов будут перераспределены.
- Новый оффер, добавленный в поток кампании через Keitaro, автоматически появится активным в приложении; его доля и доли незакреплённых офферов распределятся с сохранением закреплённых значений.
- Журнал изменений и локальные данные кампаний хранятся в MongoDB.
- Импорт существующих журналов из SQLite.

Неактивные офферы остаются в MongoDB и отображаются в приложении с долей 0%, но не отправляются в список офферов Keitaro. В Keitaro передаются только активные офферы. Если оффер удалён из общего каталога Keitaro, локальная запись и последняя доля сохраняются, но сам объект нельзя пересоздать без его исходных параметров; после восстановления оффера в каталоге он снова доступен для включения в приложении.

## Заполнение формы кампании

| Поле | Обязательно | Что указать | Пример |
|---|---:|---|---|
| Название кампании | Да | Введите название. Префикс `test_kashkarbaev_` и суффикс `_company` добавляются автоматически; фамилия, уже содержащаяся в префиксе, не дублируется. URL-alias создаётся автоматически и получает суффикс при совпадении. | `kashkarbaev` → `test_kashkarbaev_company` |
| Гео | Да | Коды стран из двух букв, разделённые запятыми, пробелами или точками с запятой. `MX`, `AU` и `RO` — примеры, а не закрытый список. Используйте коды стран, поддерживаемые Keitaro. | `AU, MX, RO` |
| Стартовый оффер | Да | Выберите существующий оффер из Keitaro через поиск по названию или ID. | `#123 · Example offer` |
| Домен | Нет* | Домен кампании из списка Keitaro. | `track.example.com` |
| Группа | Нет* | Группа кампаний из списка Keitaro. | `FORTESTS` |
| Источник | Нет* | Источник трафика из списка Keitaro. | `FORTESTS` |

`*` Домен, группа и источник можно не выбирать вручную, если приложение смогло определить значения по умолчанию из `.env` или в Keitaro доступен единственный домен. Если обязательное значение не определено, выберите его в «Дополнительных настройках» либо проверьте `DEFAULT_DOMAIN`, `DEFAULT_GROUP_NAME` и `DEFAULT_SOURCE_NAME`.

Для примера: название `Autumn AU test`, Гео `AU, MX`, выбранный оффер и домен/группа/источник создадут кампанию с отдельным гео-потоком на `GOOGLE_URL` и потоком выбранного оффера. Допустимые разделители гео — запятая, пробел и точка с запятой; коды приводятся к верхнему регистру, повторы убираются. Сейчас приложение проверяет двухбуквенный формат кода, но не сверяет его с полным реестром ISO, поэтому вводите действительные коды стран, принимаемые Keitaro.

Alias кампании не нужно заполнять вручную: приложение формирует его из названия в URL-безопасном формате и проверяет на совпадение с уже существующими alias в Keitaro. Очистка MongoDB не удаляет кампании и архив из Keitaro; Keitaro не позволяет повторно использовать имя кампании, уже находящееся в архиве.

При создании потоков используются schema-значения Keitaro API: `action` для гео-потока с URL и `landings` для потока офферов. Доступные для конкретного трекера значения можно проверить через Admin API `GET /stream_schemas`.

В редакторе изменения активности, закрепления, долей и добавления офферов сначала остаются черновиками. Если загруженные доли активных офферов дают ровно 100%, незакреплённые доли предлагаются равными черновыми значениями; они выделяются светло-жёлтым и не отправляются в Keitaro без подтверждения. Нажмите «Применить изменения», чтобы записать их в Keitaro и приложение, или «Сбросить», чтобы вернуть последнее загруженное состояние. При вводе доли остальные незакреплённые офферы распределяют остаток поровну после завершения редактирования поля. При обновлении данных или переходе к другой кампании/периоду приложение предупредит о несохранённых изменениях.

## Запуск

Требуется Node.js 22.12+ и MongoDB.

```bash
npm ci
npm --prefix server ci
npm --prefix client ci
cp .env.example .env
# Заполните KEITARO_BASE_URL и KEITARO_API_KEY
npm run dev
```

Откройте Vite-адрес, отображённый в терминале (по умолчанию http://localhost:5173). Express API работает на http://localhost:3000.

Для production:

```bash
npm run build
npm start
```

Express отдаёт собранный React-клиент из `client/dist`.

## Перенос данных из SQLite

Скрипт копирует `campaign_records` и `offer_changes` в MongoDB, восстанавливает связи офферов из журналов и сохраняет офферы, отсутствующие в последнем снимке, как неактивные. Он не меняет и не удаляет исходную SQLite-БД; повторный запуск безопасен.

```bash
npm run import:sqlite -- ./app.db
```

Замените `./app.db` на фактический путь к старой базе, если она находится в другом месте, например `npm run import:sqlite -- "/Users/you/backup/old-app.db"`. Путь `/path/to/app.db` — лишь пример и такой файл обычно не существует. Если это новая установка и старой SQLite-базы нет, пропустите импорт. Связи, которых нет в SQLite-журнале, будут синхронизированы из Keitaro при первом открытии кампании. Старый SQLite-формат не хранил признак закрепления, поэтому импортированные доли изначально не закреплены.

## Настройки

| Переменная | Назначение |
|---|---|
| `PORT` | Порт Express API (по умолчанию `3000`) |
| `MONGODB_URI` | URI MongoDB |
| `KEITARO_BASE_URL` | Адрес Keitaro |
| `KEITARO_API_KEY` | Ключ Keitaro Admin API |
| `NAME_PREFIX` | Префикс названия кампании; по умолчанию `test_kashkarbaev_` |
| `DEFAULT_GROUP_NAME` / `DEFAULT_SOURCE_NAME` | Значения по умолчанию для новых кампаний |
| `DEFAULT_DOMAIN` | Домен по умолчанию; если домен в Keitaro один, он выбирается автоматически |
| `GOOGLE_URL` | URL для гео-потока |
| `KEITARO_TIMEOUT` | Таймаут запросов к Keitaro в миллисекундах |

API-ключ хранится только в `.env`, не в клиентском приложении.

### Где взять Keitaro API key

Войдите в административную панель Keitaro, откройте меню профиля и перейдите в **Профиль → API-ключи**. Создайте ключ для приложения и скопируйте его в `KEITARO_API_KEY` в `.env`. Не публикуйте ключ и не добавляйте `.env` в Git.

`KEITARO_BASE_URL` — адрес вашей панели Keitaro, например `https://your-tracker.example`. Значение `https://tlgk.host` корректно только если именно по этому адресу открывается ваша панель. Приложение само добавляет `/admin_api/v1`; если адрес панели заканчивается на `/admin`, этот суффикс можно оставить или убрать.

## API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка состояния |
| GET | `/api/meta` | Домены, группы, источники и значения по умолчанию |
| GET | `/api/offers?q=` | Поиск офферов |
| POST | `/api/campaigns` | Создать кампанию |
| GET | `/api/campaigns?q=` | Список кампаний |
| GET | `/api/campaigns/:id?interval=today` | Кампания, потоки и статистика |
| POST | `/api/campaigns/:id/streams/:sid/offers` | Добавить или восстановить оффер |
| PATCH | `/api/campaigns/:id/streams/:sid/offers/:oid` | Переключить `active`, `pinned` или долю `share` |
| DELETE | `/api/campaigns/:id/streams/:sid/offers/:oid` | Совместимый endpoint деактивации |
| PUT | `/api/campaigns/:id/streams/:sid/offers` | Применить массив `offers` с активностью, закреплением и долями; legacy-массив `shares` также поддерживается |
| GET | `/api/debug/stream/:sid` | Сырой ответ Keitaro по потоку |
